CN Reliable File Transfer using UDP + SDN

Offline demo command sheet. Use the Copy button beside a command, then paste it into the indicated WSL Ubuntu terminal.

Before you start: Use three WSL Ubuntu terminals. Terminal 1 runs POX, Terminal 2 runs Mininet/receiver, and Terminal 3 runs the sender. Keep Terminal 1 and Terminal 2 open while testing. The commands below use the verified project path /home/arunhg/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN.

Phase 1 — Prepare the environment

ANY WSL UBUNTU TERMINAL

1. Start Open vSwitch

Starts the virtual switch service required by Mininet.

sudo systemctl start openvswitch-switch

2. Check Open vSwitch

Displays OVS status/configuration and confirms that ovs-vsctl responds.

sudo ovs-vsctl show

3. Clean old Mininet state

Run only before starting a fresh demo, not while the demo network is running.

sudo mn -c

Phase 2 — Start the POX controller

TERMINAL 1 — POX

4. Go to the POX directory

Changes directory to the installed POX source.

cd ~/pox

5. Launch the project's custom POX controller

Runs POX with Python 3.9, OpenFlow 1.0 on port 6633, link discovery, and your udpreroute component. Leave this terminal running.

"$(uv python find 3.9)" ./pox.py openflow.of_01 --port=6633 openflow.discovery udpreroute

Phase 3 — Start Mininet

TERMINAL 2 — MININET

6. Go to the project directory

Opens the folder containing topology.py, sender.py, and receiver.py.

cd ~/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN

7. Start the custom three-switch topology

Creates h1, h2, s1, s2, and s3, using OVS switches connected to POX at 127.0.0.1:6633. Keep the resulting mininet> prompt open.

sudo mn --custom ~/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN/topology.py --topo udptopology --controller=remote,ip=127.0.0.1,port=6633 --switch ovs,protocols=OpenFlow10

8. List topology nodes

Run at the mininet> prompt. Confirms the two hosts and three switches.

nodes

9. Show network links

Run at the mininet> prompt. Displays host/switch interfaces and links.

net

10. Test connectivity

Run at the mininet> prompt. Expected: 0% dropped. If first packets drop during discovery, wait briefly and run pingall again.

pingall

Phase 4 — Normal UDP file transfer

TERMINAL 2 — MININET PROMPT

11. Start receiver on h2

Run at the mininet> prompt. Starts the UDP receiver on host h2, listening on port 5001. Wait until it says “Receiver listening...” before sending.

h2 python3 -u /home/arunhg/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN/receiver.py
TERMINAL 3 — NORMAL UBUNTU SHELL ($)

12. Go to the project directory

Opens the local project folder in the third terminal.

cd ~/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN

13. Send sample.txt from h1 to h2

Runs sender.py inside h1's Mininet network namespace and sends test_files/sample.txt to h2. Use after the receiver is listening.

sudo mnexec -a $(pgrep -f 'mininet:h1' | head -1) python3 /home/arunhg/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN/sender.py /home/arunhg/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN/test_files/sample.txt

14. Compare original and received hashes

Run in Terminal 3 after receiver has saved the file. The two SHA-256 values must match.

sha256sum test_files/sample.txt received_files/sample.txt

Phase 5 — Link failure and rerouting

TERMINAL 2 — MININET PROMPT

15. Disable the direct s1–s3 link

Simulates a switch-to-switch link failure.

link s1 s3 down

16. Test connectivity after failure

Run pingall. Wait a few seconds for POX link discovery/rule updates; repeat if the first test drops packets.

pingall

In Terminal 1, watch for “Link removed”, “Forwarding rules cleared”, and route selection through switch 2 (for example, [1, 2, 3]).

17. Restart receiver on h2

After the previous completed transfer, receiver.py exits. Start it again at the mininet> prompt and wait until it says it is listening.

h2 python3 -u /home/arunhg/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN/receiver.py
TERMINAL 3 — NORMAL UBUNTU SHELL ($)

18. Send the file again while s1–s3 is down

Runs the same sender through the remaining route h1–s1–s2–s3–h2. Receiver must be running first.

sudo mnexec -a $(pgrep -f 'mininet:h1' | head -1) python3 /home/arunhg/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN/sender.py /home/arunhg/projects/CN-Reliable-File-Transfer-USING-UDP-AND-SDN/test_files/sample.txt

Phase 6 — Restore and stop

TERMINAL 2 — MININET PROMPT

19. Restore the s1–s3 link

Re-enables the direct link after the failover demonstration.

link s1 s3 up

20. Verify restored connectivity

Run pingall and confirm that the hosts can communicate again.

pingall

21. Exit Mininet

Stops the Mininet CLI and ends the virtual topology.

exit
TERMINAL 1 — POX

22. Stop POX

Press this keyboard shortcut in Terminal 1.

CTRL + C
ANY WSL UBUNTU TERMINAL

23. Final cleanup

Removes any remaining Mininet interfaces/processes after exiting the topology.

sudo mn -c
Important reminders
  • Always start the receiver before the sender.
  • Keep POX (Terminal 1) running while Mininet (Terminal 2) is running.
  • Run Mininet commands such as nodes, net, pingall, link, and h2 ... at the mininet> prompt.
  • Run sender.py and sha256sum in Terminal 3, at the normal Ubuntu shell prompt.
  • Do not run sudo mn -c while the live demonstration is in progress.
  • The sender command assumes the WSL username/home directory is /home/arunhg, matching the tested setup.
